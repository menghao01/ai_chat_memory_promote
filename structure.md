# AI Memory Chat 项目架构分析

> 本文档使用【五层系统解剖法】对项目进行完整架构分析

---

## 项目概述

这是一个**个人AI记忆系统**，核心功能是：将你的笔记、对话记录向量化存储，让AI能够基于你的历史记录进行个性化对话。就像给AI装了一个"外置大脑"，让它记住你的一切。

---

### 单一数据源 (Single Source of Truth)

- **原始数据**：`notes/` 目录下的 Markdown 文件
- **派生数据**：`vector_db/` 向量数据库（可随时重建）

**💡 看懂这一层**：数据从"原始笔记"流向"向量数据库"，所有处理都围绕 `Chunk {content, metadata}` 这个核心数据结构展开。

## 💓 第三层：动力心脏 (Drive Mechanism)

### 系统启动方式

这是一个**命令行工具集**，没有常驻服务，采用"触发式执行"：

```
┌─────────────────────────────────────────────────────────────┐
│                    触发条件 (Triggers)                        │
├─────────────────────────────────────────────────────────────┤
│  1. 首次使用 → chunk_and_index.py (全量重建)                  │
│  2. 新增笔记 → incremental_update.py (增量更新)               │
│  3. 排查问题 → check_model.py (模型检查)                      │
└─────────────────────────────────────────────────────────────┘
```

### 核心执行流程

```python
# chunk_and_index.py 主流程
main()
  ├── VectorIndexer.initialize_db()      # 加载bge-m3模型
  ├── 遍历 notes/*.md 文件
  │     └── chunk_note_file()            # 智能分块
  │           ├── 检测格式
  │           ├── 选择策略
  │           └── 生成 Chunks
  └── indexer.index_chunks()             # 存入ChromaDB
```

### 关键依赖

| 组件 | 作用 | 类比 |
|------|------|------|
| `BAAI/bge-m3` | 文本嵌入模型 | "翻译官"：文本 → 向量 |
| `ChromaDB` | 向量数据库 | "记忆仓库"：存储和检索 |
| `sentence-transformers` | 模型加载器 | "模型管家" |

**💡 看懂这一层**：系统没有后台服务，是"即用即走"的工具脚本，核心动力是**bge-m3模型**将文本转化为机器可理解的向量。

## ⚡ 第四层：神经反射 (Interaction Response)

### 事件 → 处理 映射表

| 事件 (Event) | 处理器 (Handler) | 响应动作 |
|-------------|-----------------|----------|
| 新增笔记文件 | `incremental_update.py` | 检测新文件 → 分块 → 向量化 → 追加到数据库 |
| 修改笔记内容 | `incremental_update.py` | 基于内容哈希去重 → 只添加真正新的内容 |
| 首次初始化 | `chunk_and_index.py` | 删除旧库 → 全量重建 |
| 模型损坏/缺失 | `check_model.py` | 检查缓存完整性 → 报告状态 |

### 智能分块策略 (Hybrid Chunking)

```
输入: 笔记文件
  │
  ├──► 检测到 "Chat Memo" ──────► 对话分块策略
  │                                ├── 按对话轮次分割
  │                                └── 标记 [User问] / [AI答]
  │
  ├──► 检测到 "#Topic" 格式 ──────► 主题分块策略
  │                                └── 每个 #主题 独立成块
  │
  └──► 默认 ────────────────────► Markdown分块策略
                                   └── 按 ## 标题分割
```

**💡 看懂这一层**：系统通过"文件内容特征"自动选择最佳分块策略，就像医生根据症状选择治疗方案。

## 🎯 关键设计亮点

1. **混合分块策略 (Hybrid Chunking)**：已知格式用规则，未知格式可扩展AI分析
2. **增量更新机制**：避免重复处理，只添加新内容
3. **本地模型优先**：使用缓存的bge-m3，无需联网
4. **Schema约束**：所有分块必须符合Chunk格式，保证数据一致性

## 📝 核心数据结构

### Chunk Schema

```python
{
    'content': 'chunk text content',           # 文本内容
    'metadata': {
        'filename': 'note.md',                 # 源文件名 (必需)
        'filepath': '/path/to/file',           # 完整路径 (必需)
        'chunk_id': 0,                         # 文件内序号 (必需)
        'chunk_type': 'date_entry',            # 分块类型 (必需)
        'date': '2025-11-07',                  # 日期 (可选)
        'title': 'Section title',              # 标题 (可选)
    }
}
```

### 分块大小建议

| 参数 | 值 | 说明 |
|------|-----|------|
| MIN_CHUNK_SIZE | 50 | 最小字符数 |
| MAX_CHUNK_SIZE | 2000 | 最大字符数 |
| TARGET_CHUNK_SIZE | 500 | 目标字符数 |
